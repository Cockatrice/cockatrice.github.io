◆ IconEmphasis

enum class IconEmphasis
strong

Selects which authored level of a color family a glyph uses.

Tint says which family, style says how much shape, emphasis says how loud. The three are independent: a primary action can be a line glyph in the theme's primary ink, and a quiet one can be a sticker in that family's quiet level.

Each family (neutral icon, positive, negative) stores one color per level, so emphasis is a lookup rather than a computation: the palette editor's rows are the whole source of truth. Secondary is the default and the color every icon had before the axis existed, so existing call sites keep their look. Primary is for the one action a surface exists for. Quiet is for glyphs that label rather than act, such as the magnifier inside a search field: legible, but never competing with the buttons next to it.

◆ IconStyle

enum class IconStyle
strong

Selects how a currentColor glyph is painted.

The tint decides the tone. The style decides how much shape carries it.

Line is the default and matches what every caller did before this axis existed: the recolored glyph alone, at the author's stroke weight. Use it for navigation, menu and toolbar glyphs, where a row of badges would compete with the content.

Badge reproduces the pre-#7595 ready/not-ready art: a filled disc, a dark ring and a contrast glyph derived from the tone. A filled shape draws more attention than a line, so it is opt-in per call site. It was made for the ready/not-ready icons. The add/remove/delete icons were filled glyphs with an outline and no disc, so badging them would produce art the UI never had. Authored art that carries its own colors is never badged and falls back to the asset path. Disabled icons fall back to the line glyph too, because a filled disc at full mass does not read as unavailable.

Sticker reproduces the other half of the pre-#7595 set: the filled add, remove and delete glyphs, painted with a tone gradient and a dark outline and no disc. It shares the disabled fallback for the same reason.

Renders a resolved theme SVG when it carries the currentColor sentinel.

Non-SVG assets and SVGs without the sentinel return a null pixmap so callers can fall back to their usual loading path (including legacy inversion).

Parameters
resolvedPathAsset path relative to the theme: search path, as returned by ThemeManager::assetPath (includes extension).
tintColor that replaces the sentinel: a palette role or a semantic application color. Defaults to WindowText.
sizePixel size to render at; an empty size uses the SVG's intrinsic size.
styleTreatment of the glyph: Line, Badge or Sticker. A treatment on a non-sentinel asset stays null, like the line path.
Returns
The recolored pixmap, or a null pixmap when the asset is not a sentinel-carrying SVG.

Builds a palette-aware icon from a theme: asset.

SVG glyphs may use the currentColor sentinel. A plain QPixmap snapshot cannot follow palette changes, so this returns a QIcon whose engine resolves the sentinel from the current palette every time it is asked for a pixmap. Icons therefore stay legible when the user switches between light and dark themes without recreating any actions or buttons.

Parameters
prefixAsset prefix relative to the theme: search path, with no file extension (for example icons/search), matching themePixmap().
tintColor that replaces the sentinel: a palette role or a semantic application color. Defaults to WindowText.
styleTreatment of the glyph: Line, Badge or Sticker. Defaults to Line.
Returns
An icon that follows the application palette.
