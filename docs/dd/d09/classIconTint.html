Detailed Description

Selects the color that replaces the currentColor sentinel.

A palette role follows Qt's structural palette. An application color carries meaning that QPalette cannot express, such as positive and negative states. Callers pick the role by intent; the theme owns the concrete value. Emphasis is part of the same decision: both answer how the glyph is inked.

◆ resolve()

QColor IconTint::resolve ( QIcon::Mode mode) const

Resolves the concrete color for an icon mode.

A disabled application color resolves to the derived disabled ink, the quiet level receded toward the surface, so an unavailable control does not keep its semantic color. A selected palette color keeps the WindowText -> HighlightedText swap.

Application colors are returned verbatim: the theme author stores one value per emphasis level, so the paint path does not rewrite it. The filled treatments only shape that tone's value to give a shape depth; the hue and saturation stay the author's.

Neutral label roles (WindowText, Text) resolve to icon ink rather than the raw palette color: an unauthored neutral family derives it from the live WindowText and holds the glyph to a contrast floor, because a 2px glyph in body-text ink reads thinner than the text beside it. A theme that authors the neutral icon roles overrides that derivation. Semantic roles keep the hue the call site asked for.

Emphasis selects the family's authored variant, so the palette editor's rows are the whole source of truth. A caller that names a variant explicitly (a strong or soft role) pins that level at every emphasis.
